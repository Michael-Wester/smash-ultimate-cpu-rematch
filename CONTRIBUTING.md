# Contributing

Start with a small branch from the latest `main`. For a large change, describe the
problem and intended outcome in an issue first; a small fix can go straight to a PR.

1. Follow the [README setup](README.md) and run the repository check locally.
2. Make one coherent change. Add meaningful tests when application behavior exists
   and changes; update affected docs and configuration.
3. Open a PR with a clear title, the reason for the change, and validation results.
   List anything you could not verify. Remove unused template comments.
4. Resolve review feedback and wait for checks on the latest commit before merging.

Use **Squash and merge** so each PR contributes one commit to `main`. The PR title
and description should describe the final change; they become the default squash
commit message. Working commits can be informal. Start a new branch after merging
instead of continuing to reuse the squashed branch.

Never include secrets or personal information in issues, logs, screenshots, or PRs.
For a sensitive report, contact the repository owner privately through an existing
trusted channel. Add a project-specific reporting contact before public release.
